Proof you own the code an AI wrote.

The tell of vibecoding is a premature "done." This is a working method that withholds it — earned done, not claimed done — with the first measured data showing it holds.

The mechanism

Prediction before reveal

Agentic coding hands you speed and quietly takes the act of coding — and with it the things seniority is made of: knowing why each decision was made, and being able to defend and evolve what shipped. ratify puts that back as a measurable act.

At every design decision, you state what you expect before the tool reveals its recommendation. The gap gets logged — predicted, surprised, or no-opinion. You cannot rubber-stamp a question you had to answer first, and you cannot back-fill a prediction you already recorded.

  • Stated before the reveal, logged either way — the record can't be gamed after the fact.
  • Misses are recorded, not hidden — every surprise and blind spot becomes a specific thing to go study.
  • "Approve" is the weakest signal — what's tracked is foresight and authorship, not consent.

Instead of vibecoding

Earned done, not claimed done

Vibecoding's defect isn't bad code — it's a premature "done." Three places this system withholds it until I've predicted, judged, or ruled — each proven by a real incident on Runway:

Stops at the unclear calls and asks

instead ofauto-picking a handling and calling it done

Three genuinely ambiguous cases — it surfaced each as "what's the right move?" and left the decision to me. Each shipped in the repo as a documented, owned decision with a strict tripwire, so none can be silently dropped.

Surfaces the edge cases around load-bearing behavior — and makes me rule

instead ofmaking the happy path work and calling it done

It caught a distinction I'd have missed: an empty result (isolate it) versus an integrity failure — the engine miscounting, which corrupts every result — where the whole run must abort. Worst case, an unhandled case ships as a known, documented limitation, never a silent surprise.

Runs the team's review loop — me predicting first — at solo speed

instead ofdeciding alone and leaving me to catch up

A decision approved as "should withstand existing tests" broke one on reveal — then surfaced a second under-priced cost during the build. It went back through full ratification at true cost before shipping — the loop a team runs in review, run solo without losing the ownership.

Honest status

Early evidence, not a study. One project, ~39 logged decisions, four sittings. It's a living research program — version-stamped, dated, changelog-visible. As of this week it captures automatically across every project, so the record compounds from here.

The silence was the data accumulating. This is where it goes visible.
